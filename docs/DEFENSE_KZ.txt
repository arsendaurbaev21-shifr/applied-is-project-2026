QAZCARGO ҚОРҒАУҒА АРНАЛҒАН ҚЫСҚА БАЯНДАМА

Менің жобам Қазақстан қалалары арасындағы автомобильмен жүк тасымалын басқаруға арналған. Клиент маршрут пен тарифті таңдап, жүктің салмағын, көлемін, қаптама санын және алу күнін көрсетеді. Әкімші тапсырысты растайды, көлік пен жүргізуші тағайындайды, тасымал мәртебесін және төлем есебін жүргізеді.

Жүйе үш қабаттан тұрады. HTML, CSS және JavaScript браузер интерфейсін жасайды. JavaScript fetch арқылы Python Flask API-ға сұрау жібереді. Flask сессияны, рөлді, дерек иесін және мәндерді тексеріп, pyodbc пен ODBC Driver 18 арқылы SQL Server-ге параметрленген сұрау орындайды. Транзакция commit болса, дерек тұрақты сақталады. Қате болса rollback орындалады.

Дерекқорда 17 кесте және 21 сыртқы кілт байланысы бар. Он үш кесте тасымалға арналған; Users, Documents, SupportTickets және TicketMessages аккаунт, файл және қолдау қызметтерін қосады. Екі кабинет бір QazCargo базасын оқиды. Әкімші өзгерткен деректі клиент жаңарту батырмасымен немесе тапсырыс тізімінің автоматты жаңаруымен көреді.

Көрсету реті: клиенттің жаңа өтінімі → әкімшідегі сол тапсырыс → растау → рейс → төлем → клиенттегі жаңа мәртебе → SSMS-та JOIN сұрауы → құжаттың байт көлемі → баспа.

СҰРАҚ ЖАУАП

Сайтың не туралы?
Қазақстан қалалары арасындағы жүк тасымалын жоспарлау, бақылау және есепке алу туралы.

Неге 17 кесте?
Әр нысан бөлек сақталады: клиент, қала, маршрут, тариф, көлік, жүргізуші, тапсырыс, жүк, рейс, төлем, тарих, аккаунт, файл және қолдау. Қайталау азайып, байланыстар FK арқылы тексеріледі. 13 негізгі кестеге 4 аккаунт/құжат/қолдау кестесі қосылды.

PK және FK деген не?
PK — бір жолды бірегей анықтайтын кілт, мысалы Orders.OrderID. FK — басқа кестедегі PK-ге сілтеме, мысалы CargoItems.OrderID. Ол жоқ тапсырысқа жүк тіркеуге жол бермейді.

База мен сайтты қалай қостың?
Браузер fetch → Flask API → pyodbc → ODBC Driver 18 → SQL Server. Қосылым баптауы .env ішінде. Әдепкіде Windows Authentication.

Әкімшінің өзгерісі клиентте қалай көрінеді?
Әкімшінің өзгерісі SQL-ге commit болады. Клиент өз API сұрауын жібергенде сол базадан соңғы рұқсат етілген жолдарды алады. Клиент ClientID мәні сессиядан анықталады.

Сайтқа енгізілген дерек SQL-де сақталғанын қалай дәлелдейсің?
Сайтта өтінім жасап, оның OrderNumber мәнін көрсетемін. SSMS-та database/03_verify.sql сұрауын орындаймын. Orders, Clients, Routes, Cities, CargoItems, Trips және Payments байланыстары сол өтінімді көрсетеді. Серверді қайта қосқан соң жазба сақталады.

SSMS пен SQL Server айырмасы қандай?
SQL Server — деректерді сақтайтын және сұрауды орындайтын қызмет. SSMS — сол қызметті басқаруға арналған графикалық бағдарлама. SSMS жабылса да, қызмет пен Flask қосулы болса сайт істейді.

Құжат байттары қайда сақталады?
Documents.Content VARBINARY(MAX) ішінде. FileSize пен DATALENGTH(Content) теңдігін CHECK тексереді. Тізім тек метадерек береді; файл API-ы иелікті тексергеннен кейін байттарды қайтарады.

Терминал жабылса не болады?
Python сервері тоқтайды, браузер API-ға қосыла алмайды. SQL деректері сақталады. START.bat қайта іске қосады.

Баға қалай есептеледі?
BasePrice + DistanceKm × PricePerKm + SUM(WeightKg) × PricePerKg. Екі ондыққа ROUND_HALF_UP/SQL ROUND. WeightKg — позициядағы толық салмақ, Quantity-ге көбейтілмейді.

Бір уақытта екі төлем жіберілсе ше?
API жазбалары сериализацияланған транзакция мен қолданбалық құлыпты қолданады. SQL триггері төлем жиынтығын бағамен салыстырады. Артық өзгеріс кері қайтады. Бұл сценарий екі қатар сұраумен нақты SQL Server-де тексерілді.

Бұл нейрожелі ме, банк жүйесі ме?
Жоқ. Қысқа көмек — ережеге негізделген нұсқаулық. Төлем бөлімі әкімші тіркейтін оқу есебі; банк картасынан ақша алу, email сервисі және нақты AI интеграциясы қосылмаған.
