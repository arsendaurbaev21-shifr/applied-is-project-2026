8 ЗЕРТХАНА БАҚЫЛАУ СҰРАҚТАРЫ
Даурбаев Арсен, ИС-24А

1. Интеграциялық тестілеудің негізгі мақсаты қандай?
Бірнеше компоненттің бірге дұрыс жұмыс істеуін тексеру: HTTP сұрауы валидациядан өтіп, дерекқорда дұрыс өзгеріс тудыруы және жауаптың келісімшартқа сай болуы керек.

2. Unit Testing және Integration Testing айырмашылығы неде?
Unit жеке функцияны оқшаулайды, мысалы пароль валидациясы. Integration бірнеше шынайы қабатты қосады: FastAPI, SQLModel және SQLite немесе Flask, сессия және SQL Server.

3. REST API статус кодтары нені білдіреді?
200 — сәтті оқу/өзгерту, 201 — жасалды, 204 — денесіз сәтті өшіру. 400 — JSON синтаксисі қате, 401 — кіру қажет, 403 — құқық жоқ, 404 — жазба жоқ, 409 — күй/DB қайшылығы, 422 — семантикалық валидация қатесі.

4. Жүктемелік тестілеудің қандай түрлері бар?
Load күтілетін жүктемені, stress шектен жоғары жүктемені, spike кенет өсуді, endurance ұзақ жұмыс тұрақтылығын тексереді. Мұнда 5/20/50/100 пайдаланушыға арналған сатылы load сценарийлері орындалды.

5. Response Time және Throughput нені сипаттайды?
Response Time бір сұрауға кеткен уақыт, throughput секундтағы аяқталған сұрау саны. Орташа мәнмен бірге P95/P99 баяу жауаптардың үлесін көрсетеді; error rate бөлек есептеледі.

6. SQL транзакция тұтастығы қалай қамтамасыз етіледі?
Бір операцияның өзгерістері commit арқылы бірге сақталады. Қате болса rollback барлығын кері қайтарады. PK, FK, NOT NULL және CHECK шектеулері жарамсыз күйге жол бермейді; тестте жүк жазбасын әдейі бұзып тексерілді.

7. Қауіпсіздік тестілеуінің міндеттері қандай?
Қате деректі, рұқсатсыз әрекетті және құпия ақпараттың жариялануын анықтау. Аутентификация, рөл, CSRF, сессияны қайтарып алу, пароль саясаты және жауап/лог мазмұны тексерілді.

8. pytest не үшін қолданылады?
Тесттерді табады, fixture арқылы орта дайындайды, assert нәтижесін көрсетеді және JUnit есебін сақтайды. Parametrize бір ережені бірнеше қалыпты/шекаралық/қате мәнмен тексеруге ыңғайлы.

9. CI/CD сапаға қалай әсер етеді?
CI әр өзгерісте тест пен жинауды қайталап, қате кодты ерте көрсетеді. Бұл жобада pytest, Bandit, Docker build және HTTP/persistence автоматтандырылған. Артефакт сақталады; сыртқы production жүйесіне автоматты deployment қосылған жоқ.

10. Автоматты тестілеудің шектеулері қандай?
Тест тек жазылған сценарийлерді тексереді. Нақты браузер қолайлылығы, барлық қауіпсіздік жағдайлары және production көлемі толық қамтылмайды. Бір компьютердегі қысқа load нәтижесі бүкіл жүйенің шегін дәл анықтамайды.

11. Жүктемеге шыдамаса қандай өзгеріс ұсынуға болады?
Алдымен сұрау санын, индекс пен баяу SQL-ді өлшеу керек. Мұнда N+1 жойылды. Келесі қадамдар: оқу кэші, сүзгіге сай индекс, PostgreSQL, worker санын сынау және ауыр тапсырмаларды кезекке шығару. Өлшеусіз бірнеше worker қосу SQLite жазу шектеуін шешпейді.

12. Нәтижелерді құжаттау неге маңызды?
Орта, дерек көлемі, команда, уақыт, HTTP жауап және бастапқы журнал сақталса, басқа адам нәтижені қайталай алады. Сәтсіз CI мен түзетуден кейінгі run қателіктің қалай табылып, жойылғанын дәлелдейді.
