ЖОБАНЫҢ МАҚСАТЫ

QazCargo — жүк тасымалдау тапсырыстарын басқару жүйесі.
Негізгі сайт бұрын Flask + SQL Server арқылы жасалған.
Зертхана талабына сай оған FastAPI + SQLModel + Streamlit оқу модулі қосылды.
Оқу модулі негізгі Cargo-дағы клиент, тапсырыс және жүк ұғымдарын қолданады.
Оның SQLite базасы бөлек: негізгі SQL Server деректерімен синхрондалмайды.

1-ЗЕРТХАНА — ЖОБАЛАУ ЖӘНЕ ОРТАНЫ ДАЙЫНДАУ

Жасалған жұмыс:
• Пәндік аймақ ретінде Cargo жүк тасымалдау жүйесі таңдалды.
• Клиент, тапсырыс, жүк түрі, жүк позициясы анықталды.
• Кестелердің байланысын көрсететін ER диаграммасы жасалды.
• Python виртуалды ортасы, тәуелділіктер және Git/GitHub дайындалды.
• Дерекқор, API және интерфейс бөлек модульдерге бөлінді.

Көрсететін файлдар:
docs/labs/qazcargo-er.png — ER диаграммасы;
labs/lab_1_2/ — модуль құрылымы;
requirements-labs.txt — кітапханалар; .gitignore — Git-ке кірмейтін файлдар.

Қорғауда айту:
«Бірінші зертханада пәндік аймақты анықтап, архитектураны жобаладым.
Клиент, тапсырыс және жүк түрлерінің байланысын ER диаграммасында көрсеттім.
Python ортасын дайындап, жобаны дерекқор, API және интерфейс қабаттарына
бөлдім. Кодты Git арқылы сақтап, GitHub-қа жүктедім».

2-ЗЕРТХАНА — SQLMODEL ЖӘНЕ ДЕРЕКҚОР

Жасалған жұмыс:
• 8 SQLModel кестесі құрылды: Clients, Orders, CargoTypes, CargoItems,
  Cities, Routes, VehicleTypes, Tariffs.
• PK — жазбаның бірегей кілті; FK — басқа кестеге сілтеме енгізілді.
• Clients → Orders: бір клиенттің бірнеше тапсырысы бар (1:N).
• Orders ↔ CargoTypes: бір тапсырыста бірнеше жүк түрі болады;
  бір жүк түрі бірнеше тапсырыста кездеседі (N:M).
• CargoItems осы байланысты, салмақты, көлемді және дана санын сақтайды.
• init_db кестелерді құрады; seed.py бастапқы оқу мысалдарын енгізеді.
• Алғашқы толтыруда 26 жазба: жеті кестеде 3-тен, CargoItems-та 5.
• verify_db.py сыртқы кілттер мен ORM байланыстарын тексереді.

Көрсететін файлдар, labs/lab_1_2/ ішінде:
database/models.py — кестелер мен байланыстар;
database/db.py — engine, init_db және Session;
seed.py — оқу деректері; verify_db.py — тексеру.

Қорғауда айту:
«Екінші зертханада ER моделін SQLModel кластарына айналдырып, SQLite
базасында кестелер құрдым. Бірге-көп және көпке-көп байланыстарды PK/FK
арқылы іске асырдым. Оқу деректерін енгізіп, байланыстарды тексердім».

3-ЗЕРТХАНА — GET, POST ЖӘНЕ ВАЛИДАЦИЯ

Жасалған жұмыс:
• FastAPI сервері және Swagger құжаттамасы қосылды.
• GET /api/orders — барлық тапсырысты оқу.
• GET /api/orders/{id} — бір тапсырысты оқу; табылмаса 404.
• POST /api/orders — тапсырыс пен жүк позицияларын жасау; нәтиже 201.
• Pydantic типтерді және шектеулерді тексереді.
• Теріс салмақ, бос жүк тізімі, жарамсыз күн үшін 422 қайтады.
• Depends(get_session) әр HTTP сұрауына жеке Session береді.
• ID, нөмір, уақыт, бастапқы мәртебе және бағаны сервер береді.

Көрсететін файлдар, labs/lab_1_2/ ішінде:
main.py — сервер; routers/orders.py — маршруттар;
schemas.py — сұрау/жауап үлгілері; services.py — сақтау және баға есебі.

Қорғауда айту:
«Үшінші зертханада дерекқормен жұмыс істейтін REST API құрдым. GET арқылы
тапсырыстарды оқимын, POST арқылы жаңа тапсырыс жасаймын. Pydantic қате
деректі қабылдатпайды, Depends әр сұрауға жеке сессия береді. Swagger
арқылы дұрыс және қате сұрауларды тексердім».

4-ЗЕРТХАНА — PATCH, DELETE ЖӘНЕ СҮЗГІЛЕУ

Жасалған жұмыс:
• PATCH /api/orders/{id} — тек жіберілген өрістерді өзгерту.
• model_dump(exclude_unset=True) жіберілмеген өрістерді сақтайды.
• notes=null ескертуді тазартады; міндетті өрістерге null қабылданбайды.
• DELETE /api/orders/{id} — тапсырыс пен оның жүк позицияларын бір
  транзакцияда өшіру. Нәтиже 204, жауап денесі бос.
• search — нөмір немесе клиент атауы бойынша іздеу.
• min_price/max_price — баға аралығы; client_id/status — қосымша сүзгі.
• offset/limit — нәтижелерді бөліктермен алу.
• Жоқ немесе өшірілген ID үшін 404 қайтады.
• Өзгерту/өшіру тек New күйіндегі оқу тапсырысына рұқсат етіледі.

Қорғауда айту:
«Төртінші зертханада CRUD циклін аяқтадым. PATCH тек таңдалған өрісті
өзгертеді, DELETE тапсырысты жүк позицияларымен бірге өшіреді. Іздеу,
баға бойынша сүзгілеу және беттеу қостым. Қате ID, null және қате диапазон
жағдайларын өңдедім. Оқу модулінің 26 автоматты тесті өтті».

МҰҒАЛІМГЕ КӨРСЕТЕТІН СЦЕНАРИЙ

1. ER диаграммасын және models.py ішіндегі байланыстарды көрсетіңіз.
2. FastAPI-ді F5 арқылы қосып, http://127.0.0.1:8000/docs ашыңыз.
3. GET /api/orders → Try it out → Execute: бастапқы тапсырыстарды көрсетіңіз.
4. POST ішіндегі дайын мысалды жіберіңіз. Қайтарылған ID-ді жазып алыңыз;
   оның мәні әр жаңа тапсырыста өзгеруі мүмкін.
5. Салмақты теріс етіп жіберіп, 422 қатесін көрсетіңіз.
6. Жаңа тапсырыстың ID-імен PATCH жіберіңіз:
   {"notes": "Алушыға алдын ала хабарласу"}
   Баға мен басқа жіберілмеген өрістер сақталғанын көрсетіңіз.
7. GET тізімінде search=LAB, min_price=100000, max_price=200000 беріңіз.
8. Жаңа жасаған оқу тапсырысын DELETE арқылы өшіріңіз: 204.
9. Сол ID-ге GET жіберіңіз: 404.
10. Терминалда тест нәтижесін көрсетіңіз:
    .\.venv\Scripts\python.exe -m unittest labs.lab_1_2.test_lab labs.lab_1_2.test_crud -v
