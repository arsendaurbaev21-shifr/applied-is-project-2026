## Осы компьютердегі дайын күй

2026 жылғы 18 қазанда осы жаңа папкада Python ортасы жасалды, `localhost` серверінде жаңа QazCargo базасы және оның 17 кестесі құрылды. Бұрынғы QazCargo13 базасы сақталды. Жаңа жұмыс базасында тек оқу анықтамалықтары бар; тест аккаунттары мен тест тапсырыстары бөлек уақытша базаларда тексерілді.

**Сізге қалатын жеке қадам:** `SET_ADMIN.bat` іске қосып, әкімшінің email-ын, аты-жөнін және өз құпиясөзіңізді енгізіңіз. Құпиясөз кемінде 10, ең көбі 128 таңба. Теру кезінде әріптер көрінбейді — бұл қалыпты. Ортақ дайын әкімші паролі жоқ. Содан кейін күнделікті `START.bat` қолданыңыз. Осы дайын базаға FIRST_RUN арқылы reset жасаудың қажеті жоқ.

ZIP басқа компьютерге көшірілсе, төмендегі алғашқы орнату қадамдарын орындаңыз. ZIP ішінде .env, .venv және жеке құпиясөздер болмайды.

## Қажет бағдарламалар

- Python 3.12 немесе жаңарақ 64 bit, Python launcher (`py`) және pip. Осы ортада Python 3.14 тексерілді.
- Microsoft SQL Server қызметі. SSMS-ті ғана орнату SQL Server қызметін орнатумен бірдей емес.
- SQL Server Management Studio 22 — базаны қарап, SQL сұрауларын орындауға арналған.
- Microsoft ODBC Driver 18 for SQL Server, 64 bit.
- Visual Studio Code. Толық Visual Studio қолдансаңыз, Python development workload қажет.

Ресми жүктеу беттері: [Python](https://www.python.org/downloads/windows/), [SQL Server](https://www.microsoft.com/sql-server/sql-server-downloads), [SSMS](https://learn.microsoft.com/ssms/install/install), [ODBC Driver](https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server), [VS Code](https://code.visualstudio.com/download).

## Алғашқы орнату

1. SSMS ашып, Windows Authentication арқылы серверге қосылыңыз. Connect → Server name мәнін есте сақтаңыз. Ол `localhost`, `.\SQLEXPRESS`, `КОМПЬЮТЕР\INSTANCE` болуы мүмкін. Осы компьютерде `localhost` қосылымы тексерілді.
2. `FIRST_RUN.bat` іске қосыңыз. Ол Python virtual environment жасап, requirements.txt пакеттерін орнатады.
3. Server сұрағында SSMS-тағы сервер атауын енгізіңіз. Enter — localhost.
4. Орнатқыш жаңа `.env` жасап, кездейсоқ тұрақты APP_SECRET жазады. Қосылым Windows Authentication арқылы болады.
5. QazCargo жоқ болса, 01 және 02 SQL файлдарын ретімен орындайды. Бар болса, әдепкі әрекет — сақтау және тоқтау. Reset қажет болғанда ғана RESET, одан кейін дәл QazCargo деп теру сұралады. Reset барлық жазбаны алмастырады, автоматты көшіру жоқ.
6. Әкімші email-ы, аты-жөні және өз құпиясөзіңізді екі рет енгізіңіз. Бұл аккаунт SQL Users кестесіне scrypt хешімен сақталады.
7. READY шықса, орнату аяқталды. Күнделікті START.bat қолданыңыз.

Егер база жасалып, әкімші қадамы ғана үзіліп қалса, FIRST_RUN-ды reset үшін қолданбаңыз. SET_ADMIN.bat арқылы әкімшіні жасаңыз. Бұл команда тапсырыстарды жоймайды.

## Күнделікті қосу және тоқтату

```powershell
.\START.bat
```

Браузерде http://127.0.0.1:5000 ашыңыз. Егер сервер осы адреске қосулы болса, екінші көшірмесін іске қоспаңыз. START сервері тек жергілікті 127.0.0.1 адресін тыңдайды.

- Әкімші: `/login?role=admin` → өз email/пароліңіз → `/admin`.
- Клиент: `/login` → Тіркелу → бөлек email → `/customer`.
- Екі рөлді қатар көрсету: қалыпты браузерде әкімші, инкогнито терезесінде клиент. Бір профильдің жай қойындылары cookie сессиясын бөліседі.
- Терминал ашық тұруы керек. Ctrl+C арқылы тоқтатыңыз. «Terminate batch job (Y/N)?» шықса, Y → Enter.
- Сервер тоқтағанда сайт жауап бермейді; SQL-дегі жазбалар жойылмайды. START.bat қайта қосылғанда сол база оқылады.
- HTML/CSS/JS өзгерткенде Ctrl+S, браузерде Ctrl+F5. Python өзгергенде серверді қайта қосыңыз.
- Live Server/Go Live және HTML файлын екі рет ашу Flask серверінің орнын алмастырмайды.

## .env параметрлері

`.env.example` тек үлгі. `.env` ішінде нақты жергілікті мәндер болады. Оны ортақ чатқа немесе ZIP-ке салмаңыз.

```ini
DB_SERVER=localhost
DB_DATABASE=QazCargo
DB_AUTH=windows
DB_DRIVER=ODBC Driver 18 for SQL Server
DB_TRUST_CERTIFICATE=yes
APP_TIMEZONE=Asia/Qyzylorda
SQL_TIMEZONE=Qyzylorda Standard Time
COOKIE_SECURE=0
PORT=5000
```

SQL Authentication керек болса, DB_AUTH=sql және DB_USER/DB_PASSWORD мәндерін тек `.env` ішінде көрсетіңіз. SQL мәндері ODBC connection string ішінде қауіпсіз қапталады. Windows аккаунтына жаңа база құру құқығы болмаса, базаны SQL әкімшісі орнатады. Күнделікті қосылымға қажетті dbo объектілерін оқу/жазу/орындау құқықтары керек.

APP_TIMEZONE — Python/IANA атауы, SQL_TIMEZONE — соған сәйкес Windows SQL time zone атауы. Екеуі бір аймақты көрсетуі керек. UTC DATETIME2 деректер интерфейсте осы аймаққа ауысады. PickupDate тек күн болып қалады.

DB_TRUST_CERTIFICATE=yes жергілікті өзіндік сертификатты қабылдау үшін берілген. Интернетке шығару үшін сенімді TLS сертификаты, HTTPS, COOKIE_SECURE=1, reverse proxy және жеке deployment баптауы қажет; бұл жеткізілім жергілікті оқу режиміне арналған.

## Негізгі ережелер

New → Confirmed → InTransit → Delivered. New/Confirmed → Cancelled ауысуы төлем жоқ кезде ғана мүмкін. Клиент тек өзінің New тапсырысын тоқтатады. Жүк пен баға New/Confirmed кезінде, төлем мен белсенді рейс болмағанда өңделеді. Расталған тапсырыстың соңғы жүгін өшіруге болмайды.

Қолданылған тарифтің есептеу параметрлері өзгермейді: жаңа баға үшін жаңа тариф қосыңыз, ескісін белсенді емес етіңіз. Қолданылған бағыттың қалалары өзгермейді. Қашықтық түзетілсе, бұрынғы QuotedAmount сақталады; жаңа тапсырыстар жаңартылған қашықтықпен есептеледі. Бір қалалар жұбына қайталанатын бағыт қосылмайды.

Бір тапсырысқа бір рейс жолы. Қайта жоспарлау үшін Confirmed тапсырыста Planned/Cancelled рейс өңделеді. Көлік/жүргізуші белсенді, көлік түрі тарифке сай, сыйымдылық жеткілікті болуы керек. Уақыттар қабаттасса, SQL өзгерісті қабылдамайды. Бірдей шекарадағы аралықтар, мысалы 10:00-де аяқталу және 10:00-де басталу, қабаттасу емес.

Шолуда Cancelled тапсырыстардың бағасы қарыз сомасына қосылмайды. Есепте таңдалған сүзгіге кірген барлық жолдың тарихи бағасы қосылады; Cancelled жолдарын алып тастау керек болса, мәртебе сүзгісін қолданыңыз.

## Резерв және қауіпсіз қалпына келтіру

`BACKUP.bat` QazCargo үшін COPY_ONLY, CHECKSUM резервін жасап, RESTORE VERIFYONLY WITH CHECKSUM орындайды. SQL Server қызметінің стандарт backup папкасы қолданылады. Нақты жол экранға және BACKUP_LOCATIONS.txt файлына жазылады. Бұл файлдарды ZIP-ке қоспаңыз.

Reset тек QazCargo/QazCargo13 allowlist-іне арналған функциямен, дәл атауды растағанда орындалады. Орнатқыштың қалыпты ағыны QazCargo13-ке тимейді. Backup немесе VERIFYONLY қатесі DROP-қа жеткізбейді, база MULTI_USER күйіне қайтарылады. VERIFYONLY толық қалпына келтіру сынағын алмастырмайды.

Қалпына келтіру: SSMS → Databases → Restore Database → Device → .bak. Мақсат атауын тексеріңіз. Мүмкіндігінше бөлек тексеру базасына restore жасаңыз. Жаңа QazCargo үстінен қалпына келтіру оның жаңа жазбаларын алмастырады. Ескі папкаларды жаңа сайтты және резервті өзіңіз тексергеннен кейін ғана тазалаңыз.

| Кіру шектелді | 5 қатеден кейін 10 минут күтіңіз. Әкімші паролін SET_ADMIN.bat арқылы жергілікті қалпына келтіріңіз. |
| Беттің дерегі ескі | Жаңарту батырмасы немесе Ctrl+F5; JavaScript қателерін браузер Console-дан тексеріңіз. |

## Тесттер

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Интеграциялық тесттер нақты SQL Server-де бірегей `QazCargo_Test_...` уақытша базасын құрып, соңында тек сол базаны жояды. Оған CREATE DATABASE құқығы керек. Жұмыс QazCargo базасының жазбаларына тест деректері енгізілмейді. Installer unit test-тері сыртқы SQL-ді қажет етпейді: `-m pytest tests/test_installer.py`.

Нақты орындалған тексерулер мен шектеулер — VALIDATION.txt. Толық қазақша түсіндірме — docs/QazCargo_Tusindirme.docx. SQL метадеректері — docs/schema.json. Код картасы — docs/PROJECT_GUIDE.txt. Қорғау мәтіні — docs/DEFENSE_KZ.txt.
